# SPEC：CV / 简历

针对 CV 这个去处的规则。此处不含事实——事实经第 5 节从 `wiki/` 来。

## 1. 受众与目标

- 读者：先是 ATS（按关键词与结构解析），然后是一个花 30–60 秒扫读的人。
- 决定：这个候选人是否贴合所投职位，值得打个电话。
- 优化目标：机器可解析、按职位调整顺序、一个年代一页的密度。

## 2. 结构

| # | 区块 | 内容 |
|---|---|---|
| 1 | 页眉 | 姓名、城市、一个联系方式、档案链接 |
| 2 | 摘要 | 3–4 行：角色、年限、技术栈、领域 |
| 3 | 经历 | 倒序；每个职位一块，写明雇主，客户在行内点明 |
| 4 | 教育 | 学位、院校、校区、年份 |
| 5 | 技能 | 按类别分组，不要平铺 |
| 6 | 语言 | 语言 + 等级 |
| 7 | 证书 | 名称、颁发机构、日期 |

CV 针对每次投递的定制方式是**重排与重新加权**，而不是每次重新编一段摘要。把针对不同角色的版本留在 `drafts/` 里，以便 diff。

## 3. 硬上限

| 约束 | 取值 | 最近实测 |
|---|---|---|
| 长度 | 1–2 页（8 年以上瞄准 2 页） | <measure> |
| 交付格式 | PDF，文字可选中 | – |
| ATS | 不用文本框、不用多栏正文、不用表格做主布局、不用承载语义的图标 | – |
| 字体 | 一种字族，正文 ≥10pt | – |
| 照片 | <按市场决定；在此一次性写明> | – |
| 文件名 | `<name>-<role>-<year>.pdf` | – |

超出页数上限时的**裁剪优先级**：

1. 最老的职位 → 各压缩成一行，保留雇主、职位名、日期。
2. 技能列表 → 去掉目标职位未提及的类别。
3. 教育细节 → 只留学位 + 院校。
4. 永不压缩当前职位；面试靠它。

## 4. 语言版本

每种语言一份 CV，同结构、同事实。摘要里的资历句必须与档案里的措辞一致，尽可能逐字相同——CV 与档案不一致是招聘者最容易注意到的不一致。

## 5. 事实映射

| 区块 | 取自 |
|---|---|
| 摘要 | `wiki/entities/person-*` |
| 经历的时段、办公形式 | `wiki/entities/employer-*` |
| 职责、客户 | `wiki/entities/position-*`、`wiki/entities/client-*` |
| 技能 | `wiki/concepts/skill-*` |
| 教育 | `wiki/entities/education-*` |
| 证书、语言 | `wiki/entities/person-*` |

## 6. 偏差登记簿（结构性）

有些 CV 是刻意偏离*原件*的——旧草稿说一套，已确认的时间线说另一套。把这类偏差连同裁定记在这里，免得反复扯皮：

| 偏差 | 裁定 |
|---|---|
| <旧草稿写 X，已确认记录写 Y> | <以 wiki 为准；不要"修正"旧文件> |

不要为了对齐而编辑 `raw/`。旧文件是当时寄出内容的证据。

## 7. 禁写项

| 永不写 | 因为 |
|---|---|
| 记录支撑不了的资历词 | 面试会检验 |
| 只出现在课程里、且未标注的技能 | 常见，也很容易被抓 |
| 把客户当成雇主 | 伪造雇佣史 |
| 没有来源的百分比或"提升 X%" | 无法核实，且现在会被要求解释 |
| 单独一栏软技能 | 对 ATS 是噪音；真要写就放进摘要 |

## 8. 验收清单

- [ ] 页数在上限内，并在导出的 PDF 上核实
- [ ] PDF 文字可选中；没有内容被困在图片里
- [ ] 日期、职位名、雇主与 wiki 完全一致
- [ ] 摘要的资历措辞与档案变体一致
- [ ] 每条要点以动词开头；没有句子以 "Responsible for" 开头
- [ ] 技能已分组、去重，不超过档案的列表
- [ ] 导出文件按第 3 节命名

## 9. 发布流程

1. 复制上一版草稿，为角色定制（重排、重新加权）。
2. 导出 PDF；核实页数与文字可选中。
3. 走一遍清单；改草稿。
4. 在 `state.md` 里记录：哪个变体投给了谁、何时。投给任何地方的 CV 才算一次发布。
