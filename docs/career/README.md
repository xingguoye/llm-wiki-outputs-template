# Worked example (fictional)

Everything here is invented: names, companies, dates. It exists to show the conventions in use, because the template's rules read abstractly until you see them applied.

| File | Shows |
|---|---|
| [`source-cv-2026.md`](source-cv-2026.md) | one raw file turned into a source page — where ingestion starts |
| [`person.md`](person.md) | the page that owns cross-cutting totals (years, level, languages) |
| [`employer.md`](employer.md) | the page that owns the employment spans — the only place dates live |
| [`position.md`](position.md) | one role: period + arrangement + client attribution + optional claim IDs |
| [`decision-register.md`](decision-register.md) | rulings that must not be re-litigated every release |
| [`linkedin-draft-excerpt.md`](linkedin-draft-excerpt.md) | how a draft quotes facts by slug and measures its own limits |

Read them in that order: source → totals → spans → a role → the rulings → the rendered copy.

Two things to notice:

1. **The draft repeats no dates.** It says "the current role" and lets the wiki own the span.
2. **The decision register is boring on purpose.** Its job is to stop the same argument from recurring, not to document reasoning beautifully.
