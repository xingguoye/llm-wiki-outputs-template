# 完整示例（虚构）

这里的一切都是编的：名字、公司、日期。它存在的意义是展示四条约定在真实使用中的样子——模板的规则在读起来很抽象，直到你看见它们被用上。

| 文件 | 展示什么 |
|---|---|
| [`person.md`](person.md) | 拥有跨页总数的页面（年限、级别、语言） |
| [`employer.md`](employer.md) | 拥有雇佣时间段的页面——日期只住在这里 |
| [`position.md`](position.md) | 一个职位：时间段 + 办公形式 + 客户归属 + 可选的 claim ID |
| [`decision-register.md`](decision-register.md) | 不必每次发布都重新吵一遍的裁定 |
| [`linkedin-draft-excerpt.md`](linkedin-draft-excerpt.md) | 草稿如何按 slug 引用事实，并自己量自己的上限 |

按这个顺序读：总数 → 时间段 → 一个职位 → 裁定 → 渲染出的文案。

有两件事值得注意：

1. **草稿一个日期都不重复。** 它说"当前职位"，时间段交给 wiki 拥有。
2. **决定登记簿故意写得枯燥。** 它的职责是阻止同一个争论反复出现，不是把推理写得漂亮。
